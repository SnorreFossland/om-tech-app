# Template JSON Schema and Authoring Guidelines

This document describes the Template JSON shape used by SessionSetup, the Group Rules DSL, validation notes, and examples for program leads and implementors.

## Core contract
A Template is persisted in the database with these top-level properties (TypeScript-like):

- id: string (UUID) — generated by Prisma/DB
- name: string
- description?: string
- schema: object
  - sections: Array<Section>
  - groupRules?: GroupRules
- version: number (incremented on changes)
- createdBy?: string
- updatedBy?: string

The `schema` object contains the authorable structure used when creating sessions and rendering previews.

## Sections
A Template `schema.sections` is an ordered array. Each Section has:

- id?: string (optional client-side id)
- key?: string (optional stable key)
- title: string
- description?: string
- items: Array<Item>

An Item is a single piece of content in a section. Minimal item shape:

- id?: string
- type: string (e.g., 'text', 'notes', 'action', 'choice')
- label?: string
- placeholder?: string
- config?: object (type-specific configuration)

Implementation note: The editor exposes structured controls to manage sections and items; the renderer should be defensive (ignore unknown item types but preserve them when editing/saving).

## Group Rules (DSL)
Group rules describe how participants are grouped and roles assigned.

GroupRules shape (example):

- maxParticipants?: number
- roles?: Array<{ id?: string; name: string; count?: number }>
- assignmentStrategy?: 'random' | 'manual' | 'balanced'

Guidance:
- `maxParticipants` caps the number of participants for a session using this template.
- `roles` defines named roles and nominal counts; the editor validates that sum(role.count) <= maxParticipants when both present.
- `assignmentStrategy` affects runtime behavior; default is `random`.

## Validation rules (server + client)
Server (strong) validations:
- `name` must be a non-empty string.
- `schema.sections` must be an array; each section must have a non-empty `title`.
- `schema` must be serializable as JSON.
- Ownership: updates/deletes require creator identity (or admin role, future work).

Client (friendly) validations:
- Ensure JSON previews parse cleanly.
- Show clear messages when group rules sum exceeds `maxParticipants`.
- Prevent saving if required fields are missing.

## Audit & Versioning
- Every create/update/delete/revert writes an `audit` record containing a snapshot of the template (meta.snapshot) and any `prevSnapshot` when relevant.
- Reverts apply a snapshot atomically and increment `version`.
- Keep snapshots small; prefer referencing heavier artifacts externally if templates grow very large.

## Examples
Minimal template:

```
{
  "name": "Retrospective",
  "description": "Simple retrospective template",
  "schema": {
    "sections": [
      { "title": "Opening", "items": [{ "type": "text", "label": "Goal" }] },
      { "title": "Gather Data", "items": [{ "type": "notes", "label": "Notes" }] },
      { "title": "Decide", "items": [{ "type": "action", "label": "Actions" }] }
    ]
  }
}
```

Template with group rules:

```
{
  "name": "Role-based Workshop",
  "schema": {
    "sections": [
      { "title": "Intro", "items": [{ "type": "text", "label": "Topic" }] }
    ],
    "groupRules": {
      "maxParticipants": 12,
      "roles": [ { "name": "Facilitator", "count": 1 }, { "name": "Recorder", "count": 1 }, { "name": "Member", "count": 10 } ],
      "assignmentStrategy": "balanced"
    }
  }
}
```

## Best practices for authors
- Keep templates focused — avoid mixing too many concerns in one template.
- Use descriptive section titles and short item labels.
- When adding roles, prefer explicit counts for predictable assignment.
- Use version notes (in audit meta) to capture intent for major changes.

## Migration considerations
- When changing section keys or item IDs, provide a migration path for existing sessions (dry-run tooling planned).
- Removal of sections should surface warnings; consider adding a 'deprecated' flag rather than hard-deleting until migration completes.
